# mcplink 架构

mcplink 围绕多 MCP Server 统一接入与 MCP 转 CLI 构建。两种入口应使用同一套服务、认证和调用策略；桌面用于管理它们。目标与验收标准见[产品定位](product.md)。

## 接入结构

每个 Agent 可以使用一个 `mcplink` 聚合入口，由本机后台提供所选多个上游服务；单服务入口和终端 CLI 通过同一调用核心使用成员连接。上游定义、认证和入口服务选择由 mcplink 维护，增删服务不要求新增客户端 MCP 条目。原生直连保留为独立选项，由客户端维护调用和授权。

聚合入口在连接表中以 `transport: aggregate` 保存成员连接 ID 和稳定命名空间，使用既有连接修订、配置绑定、预览和恢复事务。入口不拥有上游账号，不能嵌套另一个入口。不同入口可选择不同成员，多个入口也可引用同一个服务账号。

`gateway.rs` 合并 tools、resources、prompts 清单，为名称及资源 URI 增加命名空间，并将调用派发给成员连接。各成员通过同一 `McpPool` 和 Vault 维护会话及 OAuth 刷新。清单有界分页；成员并行发现，单个故障通过 `_meta.mcplink.upstreamErrors` 报告，其他服务继续提供清单。工具调用固定成员、入口修订及发现时的工具契约，失败不自动重发。

上游清单统一由 `catalog.rs` 收集，按能力选择标识字段，拒绝重复或空标识、循环和无效游标，限制为 100 页及 10000 项，并在取页前后核对连接修订。聚合层按上游声明与配置跳过禁用和缺失的能力，保留成员并行发现和每成员 10 秒时限。聚合分页使用每页 100 项的固定快照。上游按种类的清单变更通知会使该类游标失效，`gateway refresh` 使相关入口的全部清单游标失效。具名查询和调用只发现名称可能对应的成员，并在派发前核对所选成员的修订与 Schema。资源读取也核对调用方指定的成员修订。内部元数据在转发前移除。

Bridge 对已支持的清单宣告 listChanged；上游通知更新连接的分类计数器，Bridge 定时比较只含入口/成员修订和计数器的摘要，通知相应客户端刷新。断开时取消监听；不会通过轮询清单或业务工具判断变化。不能处理通知的客户端仍需重载 MCP。入口服务选择保存后立即生效，不重写已绑定的 Agent 配置；原生配置迁移仍需预览和应用。

业务 Skill 由外部分发流程管理；软件只内置自身的管理 Skill。Skill 分发、模型切换及办公平台业务功能不作为产品核心。

## 当前组件与调用

- **桌面**：Tauri 2 + React/TypeScript，提供服务盘点、连接编辑、账号维护、按 Agent 查看接入、变更预览和恢复。客户端操作由安装状态和来源能力决定；打开接入窗口不纳管服务，来源导入需明确操作。
- **管理核心**：Rust `mcplink-core`，维护规范连接、SQLite 元数据、系统凭据库和配置操作日志。客户端适配器处理 TOML、YAML、JSON/JSONC/JSON5 及配置生成，复用同一规范连接和 Bridge。需要在客户端确认的内容不生成虚假的绑定或原生变更记录。完整能力见[Agent 接入](agent-discovery.md)。
- **Agent 配置来源**：每个来源保留作用域、路径、服务表及权限。编辑复用预览、哈希检查、备份和逐条恢复事务，保留未涉及设置及客户端格式；插件与托管来源保持只读。客户端审批、信任、登录缓存和插件升级由原客户端维护。具体边界见[配置适配](agent-adapters.md)。
- **工具 CLI 与管理接口**：`call` 调用精确 MCP 工具，`cli generate/inspect/check/rebind/run` 提供不含凭据的轻量命令入口；管理命令维护服务与配置。两者复用后台 RPC、认证及工具策略，使用 JSON 输出、stdin 和明确退出码。`skill show/install` 从二进制导出或安装管理 Skill，无需后台。详见 [CLI 指南](agent-cli.md)。
- **后台**：独立 `mcplink daemon`，每个数据目录单实例。Windows 关闭窗口后收起到托盘，左键显示窗口，右键可暂停共享、设置登录自启或退出托盘。登录自启使用当前用户启动项和 `--background`，窗口从创建起隐藏；重复启动复用现有桌面实例。托盘每 10 秒检查后台并按需恢复；退出托盘后代理继续运行，由后续调用按需恢复，不安装 Windows 系统服务。
- **MCP 入口**：Agent 为单服务或聚合入口启动 STDIO Bridge，通过带本地认证的 loopback HTTP 调用后台。Bridge 引用普通连接 ID 时提供单个上游，引用聚合连接 ID 时提供所选多个上游。后台用 rmcp 连接上游 STDIO 或 Streamable HTTP。

托管入口只在原生配置中保留程序路径、入口或服务连接 ID 和数据目录。聚合入口统一使用 `mcplink` 接入名称，工具/提示名称采用成员命名空间，资源 URI 以 `mcplink://命名空间/` 前缀保留上游 URI 与模板变量。单服务入口继续保留上游能力名称。

后台每项连接复用一个上游会话；多个客户端的请求由协议 ID 分流。SDK 管理握手、分页游标和 MCP 结果。转发 tools、resources、prompts 的普通请求；不宣告没有实现的 tasks、sampling、elicitation 或订阅能力。Hermes 的工具白名单、glob 和资源/提示开关由共享路径保留；不能等价转换的直连配置拒绝写入，并给出改用共享接入的提示。

Bridge 每次派发前检查后台并按需重新连接。派发后通信失败或超时返回结果待核对，不自动重发工具调用。下游取消不代表上游回滚，当前不保证跨 HTTP 管理链路传播取消通知。

共享暂停状态存入 SQLite `settings`，写入成功后才确认暂停或恢复，后台重启保持原状态。Windows 的后台、RPC 助手和上游 STDIO 服务均隐藏控制台，上游服务使用带关闭回收标志的 Job Object。macOS 和 Linux 的上游使用独立进程组，暂停、正常退出及 SIGTERM 会清理该组。SIGKILL 无法执行清理回调。

Windows 托盘和 macOS 菜单栏共用后台生命周期。关窗隐藏，普通重复启动唤起界面，登录启动时保持隐藏。退出和升级先关闭桌面请求入口及巡检，最多等待 30 秒让已接收请求完成，再停止共享后台。等待超时会恢复界面和巡检。仅退出界面也等待已接收请求完成，随后保留独立后台。`gateway.stop` 或直接终止后台会中断已派发操作并汇总一次清理结果，再释放本实例的运行锁。暂停偏好继续由 SQLite 保存。后续 Agent 调用可以按需启动后台。桌面、CLI 和后台应使用同一构建。平台细节见 [Windows](windows-background.md) 与 [macOS](macos-background.md)。

## HTTP API 接入

OpenAPI／Swagger 导入器离线生成可审阅定义，不联网解析引用、不写入连接；桌面和 CLI 复用同一转换器。执行层只理解通用请求映射、响应成功条件和敏感字段规则，不绑定具体 OpenAPI 供应商。请求头凭据在响应转换前过滤，结果与静态错误元数据分开处理；服务专用业务码解释、分页和参数换算由服务配置或 Skill 维护。

HTTP API 成员通过 `http_api.rs` 执行声明式请求映射，不建立 MCP 上游会话。`McpPool` 保留共享暂停、工具策略和修订检查，再把该类连接交给 Adapter；JSON Schema 校验同样覆盖原生 MCP 调用。HTTP API 复用原成员连接的 Vault 请求头，聚合入口及 CLI 不复制凭据。工具发现不访问上游，只有真实调用或显式配置的 probe 才能核验网络和业务访问。该成员仅宣告 tools；图片作为 MCP image 内容返回。

## 配置与数据

原生配置是客户端配置现状的来源。SQLite 保存连接摘要、入口成员、来源、绑定、修订号和操作状态，启用 WAL、外键与 schema 版本。完整上游定义及变更计划放在系统凭据库，SQLite 仅保存凭据引用。当前数据库语义版本为 5，management API 为 24。桌面、CLI、Bridge 和后台使用同一构建。修改已有连接需要最新编辑版本，显示信息编辑推进编辑版本，认证及调用继续使用原连接修订。用户标签由用户维护。

入口选择更新要求 `editVersion`，保存已有连接引用与可选工具白名单，不复制凭据。省略工具策略保留已存范围，null 沿用全局策略，空数组不开放工具。工具发现和调用都执行交集。删除成员前须先移出所有入口，删除入口时成员账号独立保留。明确选择 `replaceShared` 的迁移预览会逐条移除同一来源中所选成员的单服务共享绑定，并添加聚合条目。原生直连及未选择的条目保留。应用与恢复沿用文件哈希和条目归属保护。

预览记录连接修订、目标路径和文件哈希。应用时同一用户的各数据目录按目标文件共用私有写锁。写入在已核对的目录内进行，先保存备份和条目快照，在最终校验后登记写入意图，再原子替换文件。Unix 用目录句柄执行替换并同步文件和目录。Windows 持有各父目录的句柄，用系统替换接口保留 ACL 和命名流，并同步发布后的文件。批量操作以同一文件中的前序结果计算后续哈希，各目标分别报告结果。

替换及同步完成后，绑定、操作结果和恢复状态在同一个 SQLite 事务内提交。写入可能已发生而同步或记账未完成时，保留 pending 并保护相同条目。核对时若见预期条目，重新同步再补记。原条目仍在则判为未写入，外部修改记为冲突。来源或凭据库暂时不可用时该操作保持 pending，其余操作继续处理。恢复只修改本次条目，并核对其归属及最新有效操作。原生直连在托管定义更新后需要重新预览应用。共享连接直接使用新的托管授权。解除托管时原生文件保留。修改显示名称、账号标签会保留启停和核验状态。HTTP 地址跨源时暂停访问，并要求核对新来源的认证。

每个数据目录同时保留最多 32 份待应用预览，预览有效 10 分钟。应用完成后清理预览凭据，按原计划 ID 可重查结果。启动后在本应用和当前数据目录的凭据命名空间内回收旧计划及无主失败快照。原生整文件备份存于数据目录的 `backups/`，可能含原客户端明文凭据。Unix 使用当前用户私有权限，Windows 使用仅当前用户和 SYSTEM 的 ACL。整文件备份到期 30 天后清理，待核对条目的备份保留到恢复确认。按条目恢复使用系统凭据库中的事务快照。

## 认证

HTTP 令牌按上游要求原样保存，不自动添加 Bearer。标准 OAuth 使用 rmcp AuthorizationManager：系统浏览器、PKCE S256、state/issuer 检查、单次授权会话及 loopback 回调。支持上游动态注册或预注册应用、系统凭据库存储的客户端机密、显式 scope 和可选固定回调端口；不接管客户端私有凭据文件。授权流程准备成功后才替换原认证，配置变更使旧 grant 失效。含托管 OAuth 参数的定义经共享 Bridge 复用，不能等价转换时拒绝直连导出。

每份 OAuth grant 使用同一刷新锁。共享同一 OAuth 会话的 Bridge 和 CLI 按序发送普通 HTTP POST，避免刷新使仍在途的请求令牌失效。上游打开 SSE 响应流后即可发送下一个请求。更新、断开和回调按连接修订校验，旧授权无法覆盖新状态。断开停止新调用并删除托管令牌/grant；已派发调用的副作用不会被撤销。原客户端保存的直连凭据仍由相应客户端维护。

连接核验依据传输与 OAuth 错误类型区分认证失败和临时故障。临时故障保留 grant。明确重新检查 `needs_auth` 的连接时，在临时会话中核验已存授权。刷新返回 `invalid_grant` 时，只清除同一修订下被拒绝的 grant。

`lifecycle.rs` 集中处理定义替换、令牌更新、断开与 OAuth 提交。修改会暂停该连接的会话接收，取消启动中和运行中的同代会话，然后取得刷新锁完成提交。后继会话等待旧会话关闭后使用当前修订。OAuth 发现、注册和换令牌使用内存凭据并在管理写锁外完成，回调先校验 state 和 issuer，再按连接修订提交。重复登录、改配、断开和退出会取消相关授权任务并关闭回调监听。仅修改显示信息保留会话。

系统凭据库与 SQLite 不构成跨存储原子事务：先登记暂存引用并保存新定义，再提交其引用和连接修订，在同一 SQLite 事务内记录清理引用，成功后清理旧定义与 grant。数据库拒绝提交时保留原定义与授权；提交后的清理失败明确报告配置已保存，失效的 OAuth grant 不再用于调用。清理待办仅保存引用，在同命令重试或后台重启时继续处理，后续新授权写入前须完成旧 grant 清理。新定义未提交时发生进程退出，重启清理其暂存引用并保留原连接。OAuth 回调只有在凭据接收和状态保存均成功后才报告完成；成功提交推进连接修订，使授权完成前的探测结果与旧调用契约失效；状态保存失败时保留已接收的凭据，提示返回检查连接。

单服务 Bridge、聚合 Bridge 与 CLI 以同一成员连接 ID 取得授权。认证复用限于同一数据目录中的同一服务账号及授权范围；不跨数据目录或设备复制登录态。入口服务选择是本机调用视图，不是面向不可信进程的账号隔离机制。

本地管理 HTTP 绑定 127.0.0.1，校验 Host 和请求来源。API 24 使用独立 Vault 密钥完成双向 HMAC 持钥证明，并派生绑定实例的短寿命会话。RPC 请求与响应分别加密认证，请求在读体前验证会话头，派发前校验序号以防重放。旧协议须由其客户端退出后再启动当前后台。自动启动获得运行锁后会尝试复用历史端口；端口已被占用时选择可用端口。显式指定的端口被占用时报告错误。

HTTP MCP、OAuth 和 HTTP Adapter 复用带出站校验的客户端。DNS 解析器把校验后的地址直接交给连接器，字面地址也按同一规则分类。显式 loopback 服务可用 HTTP，HTTPS 内网目标须确认准确来源。保留或链路本地地址及本实例管理端口被禁止，系统代理配置不参与托管请求。仅 OAuth 元数据的同源读取允许有界重定向，令牌及业务请求按原地址发送一次。

OpenAPI 预览只读文件，使用受限 YAML 事件解析和单文档引用预算。后台最多允许两个导入任务同时使用阻塞线程，操作预览、工具选择和保存连接各有独立入口。文档中的本机与内网候选需要明确选址。

Bridge 的被动巡检只在收到有效的清单版本后更新摘要并比较变化。后台停止、超时或错误响应期间保留上次版本。后续实际 Agent 请求可按需启动后台。

凭据绑定于 HTTP 来源或 STDIO 启动身份。同源 HTTP 请求头可以在同一连接中重映射。STDIO 环境变量转为 HTTP API 请求头须在桌面原生确认窗口核对目标与字段，再保存并重新连接。其他接收方变化要求重新填写相应凭据。

## 代码入口

`config.rs` 适配原生格式，`engine.rs` 处理管理操作、变更与恢复，`catalog.rs` 收集上游清单，`invocation.rs` 管理工具契约与参数校验，`gateway.rs` 管理聚合入口和路由。`lifecycle.rs` 管理认证变更与凭据持久化，`mcp.rs` 管理上游会话，`oauth.rs` 管理浏览器授权任务和回调，`outbound.rs` 实施共享出站策略。`runtime.rs` 提供后台与管理客户端，`cli.rs` 提供具名 CLI、机器契约和 Skill 安装，`main.rs` 提供程序入口与 Bridge。`src/main.tsx` 是桌面功能入口。入口服务与工具范围位于 `src/GatewayDialog.tsx`，工具 CLI 工作流位于 `src/CliDialog.tsx`，连接编辑、配置来源和接入预览分别位于 `src/ConnectionEditor.tsx`、`src/SourceDialog.tsx` 和 `src/ConnectDialog.tsx`。
