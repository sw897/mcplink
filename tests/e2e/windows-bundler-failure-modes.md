# Windows 打包工具准备的失败方式

修复前先列出验收范围。通过脚本实际入口，在忽略目录中使用独立工具缓存；Windows 安装包及后续验收以同一提交的 GitHub CI 为准。

- 官方公开下载地址返回 HTTP 504：通过 GitHub CLI 的 Release API 下载指定资源，网络失败有限重试，耗尽后非零退出。
- 下载资源与固定的 SHA-256 不一致：立即拒绝，不安装或复用未验证内容。
- 缓存资源损坏：重新下载并校验；已验证缓存可离线重用。
- 已解压的工具被修改或缺文件：从已验证的压缩包重建工具目录，避免缓存损坏继续传播。
- Tauri CLI 锁定版本变化：停止并要求重新核对官方工具版本、结构和摘要。
- 凭据仅通过 CI 的 `GH_TOKEN` 环境传入；不写入命令参数、缓存或验收报告。
- Windows CI 必须实际生成 NSIS 安装包，并继续运行所有原有端到端场景；准备工具成功不能代替打包和运行验收。
