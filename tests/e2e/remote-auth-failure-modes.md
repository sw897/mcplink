# GitHub 远程 MCP：失败方式与验收

在生成 CLI 阶段两平台验收通过后实施。先从官方端点和最小只读请求复现，再决定修复范围；传输、手工 Bearer Token、预注册应用 OAuth 分别记录。

官方依据：GitHub [远程端点](https://github.com/github/github-mcp-server/blob/main/docs/remote-server.md)与[宿主集成指南](https://github.com/github/github-mcp-server/blob/main/docs/host-integration.md)。2026-11-08 核对的指南说明远程 OAuth 不提供 DCR，预注册 GitHub App/OAuth App 有客户端认证要求；手工 Token 可独立使用。固定实际 SDK、协议版本、入口、权限与验证范围，不以规范或 SDK 升级代替互操作证据。

| 失败方式 | 预期 |
| --- | --- |
| 官方 URL、传输响应或协议版本不匹配 | 从失败阶段定位，保留脱敏结论；不把所有错误归为 OAuth 或旧 SSE |
| legacy `initialize` 把 2026 版本作为默认请求，而会话绑定初始版本 | 用已实现的 legacy 协议版本初始化；覆盖 SSE、会话头、后续请求与 GET 405，不把 `invalid session` 误判成 Token 失效 |
| 代理与直连的表现不同 | 分开记录网络对照，保留环境变量代理与本地管理绕过代理的边界，不用修改全局网络设置掩盖协议失败 |
| 无令牌、无权限、应用/组织策略拒绝 | 分别说明认证与权限边界；不自动改账号、扩大 scope 或无限重试 |
| 不支持 DCR，且没有可用预注册应用 | 给出可执行的配置缺口提示；不复用其他客户端内置身份或 secret |
| 发现、注册或回调监听在授权启动时失败 | 保留原本可用的认证定义和连接模式，不先删除现有 Token 再报错 |
| 预注册应用缺少 client ID、客户端认证或固定回调配置 | 创建授权流程前明确失败，不产生看似成功的配置或泄露秘密 |
| 上游建议的 scope 与注册应用实际权限不同 | 支持明确选择 scope；GitHub App 的权限来自注册，仅在需要刷新时使用其支持的 `offline_access`，不默认为其请求资源端建议的全部 scope |
| OAuth 回调端口被占用、state 不符、会话过期或连接已更新 | 回调失败且不覆盖新授权；不静默换回调或接受旧会话 |
| 显式 scope、PKCE、client secret 的授权交换 | 按注册契约发送；秘密只走 stdin 和系统凭据库，管理输出/数据库/原生共享配置/生成 CLI 不含秘密 |
| OAuth grant 到期、刷新轮换、并发刷新或后台重启 | 复用同一托管授权，不串用旧账号或丢失轮换后的刷新令牌 |
| 机密客户端在后台重启后恢复 | 从系统凭据库重新配置客户端认证；仅恢复 client ID 不足以证明刷新可用 |
| 编辑已有 OAuth 配置 | 脱敏机密可原样保留，显式修改或清除按字段契约处理；旧授权不能串给更换后的应用身份 |
| 授权撤销、scope 缩减或令牌不可刷新 | 明确重新授权或更新凭据；不把手工更新记为 OAuth 自动刷新 |
| 工具筛选、只读入口和原始工具 Schema | 名称、类型和账号范围保持一致；CLI/Bridge 的当前筛选生效 |
| 超时、断开或服务端错误 | 保留既定结果不确定语义，不自动重放业务工具调用 |
| 直连、两个已建立的 Bridge、通用及生成 CLI | 对同一已授权测试对象得到一致的只读结果，凭据更新后继续复用连接 |

合成回归使用隔离目录和 fixture Vault；真实账号使用系统凭据库和专用测试数据目录，不进入 fixture Vault，不保存令牌、原始授权响应或业务正文。真实测试脚本和工件进入忽略目录。撤销或失效仅操作独立测试授权，不撤销日常账号凭据。

每条结果分别标明合成场景、真实上游、原生 Agent 客户端加载和所需外部依赖。真实 OAuth 须有可用的自有/授权应用注册和账号同意；缺少时保留具体阻塞，不把模拟或手工 Token 的成功记为 OAuth 通过。
