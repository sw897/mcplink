# 按连接生成 CLI：失败方式与验收

在通用调用两平台验收通过后实施，复用 `tools.describe`、`tools.call`、固定 Schema 摘要和同一管理后台。先列出失败方式，再从生成的实际命令入口验收。

拟定契约：

- `mcplink cli generate CONNECTION_ID --name NAME --output NEW_DIRECTORY --tool TOOL ...`：明确选择工具，生成轻量启动入口及版本化清单。
- `mcplink cli inspect MANIFEST`：离线检查清单，不读取凭据或启动后台。
- `mcplink cli rebind MANIFEST --connection CONNECTION_ID`：显式绑定当前数据目录中的连接；工具契约变化时要求重新生成。
- 生成入口以工具名作为子命令，支持 `--help`、参数标志及互斥的 `--stdin`。复杂参数可用 JSON stdin，不把嵌套值转成字符串。

生成物仅含数据目录身份、托管连接引用、选定工具名、输入 Schema 摘要、参数名称/类型和生成器版本；不保存端点、认证头、Token、OAuth grant、Schema 默认值/样例或机器绝对路径。运行依赖本机 mcplink，不复制整个二进制或增加 Node/Python 运行时。

| 失败方式 | 预期 |
| --- | --- |
| 缺少工具选择、非法名称、命令保留词或参数标志冲突 | 明确拒绝或标为仅支持 stdin，不静默重命名、覆盖参数或生成不可调用入口 |
| 连接、工具或可用 Schema 不存在 | 创建文件前失败，不改变原配置 |
| 输出目录已有文件、符号链接或发生并发创建 | 拒绝覆盖；保留原有内容 |
| 写入中断 | 不留下看似成功的半成品；原有文件不受影响 |
| 清单损坏、版本不支持、超限、未知字段或为符号链接 | 离线失败，错误不回显内容 |
| 在另一数据目录运行或原连接丢失 | 要求显式重新绑定，不按名称选择另一个账号 |
| 显式重新绑定 | 核对全部选定工具和契约后原子更新；保留未知并发修改 |
| 上游 Schema 变化或工具被筛选 | 运行时拒绝派发，提示重新核对或生成 |
| 托管凭据更新、OAuth 刷新、后台重启 | 已有生成入口继续工作，无需重新生成 |
| 嵌套 JSON、数组、布尔值、数值、null、Unicode、空字符串及路径空格 | 从实际启动入口保持参数类型和值，JSON/退出码与通用 CLI 一致 |
| 同时给参数标志与 `--stdin`、重复参数或未知参数 | 退出 2，不发送工具请求，不回显输入 |
| 工具 `isError`、RPC 错误或结果不确定 | 保留通用 CLI 的失败语义，不自动重放 |
| macOS、Windows | 各自执行生成入口、帮助、参数、复制/重绑、失败恢复和凭据更新，不以单平台结果替代 |

验收还须扫描生成目录，核对只包含声明的入口和清单，不含凭据及本机路径；同一工具经生成入口、通用 CLI、原生 Bridge 的有效结果一致。
