# Pi Agent 接入与 WorkBuddy 实机验收失败方式

在实现 Pi 适配和写入 WorkBuddy 测试配置前登记。使用合成服务，不修改原生账号认证或其他连接器；仅在原客户端确认本次合成服务的信任，不直接编辑信任存储。

| 失败方式 | 预期及验收入口 |
| --- | --- |
| 依据旧 Pi 包或第三方扩展猜测当前格式 | 核对官方当前发行包、配置解析器及 CLI；针对内置 MCP 适配，明确第三方替代扩展与旧版本的边界 |
| 客户端未安装仍写配置 | Pi 始终可见；只有发现实际 CLI 或用户明确选择有效启动器时允许原生写入 |
| 用户与项目来源混淆 | 用户为 `PI_CODING_AGENT_DIR/mcp.json` 或 `~/.pi/agent/mcp.json`；项目为显式选择的 `.pi/mcp.json`；不代替用户授予项目信任 |
| 项目偏好覆盖被当作完整连接 | 只有 enabled/exposure/toolExposure 的覆盖保留原样；不能作为完整上游托管或写入无关执行字段 |
| 名称与 Pi 工具命名规则冲突 | 拒绝无效服务名及仅连字符/下划线不同的冲突名称；不覆盖既有条目 |
| 动态值、工具暴露或超时改变执行语义 | 保留无关原生字段；不能等价托管的命令替换、变量引用、工具暴露、OAuth 或限制明确拒绝，不执行动态凭据命令 |
| 原生字段类型错误被转换成默认值 | 对 enabled 和命令、URL、cwd 等字段先检查类型，不能把字符串 false 当成已启用，也不能丢弃错误的工作目录 |
| JSON 注释、无关偏好或并发编辑丢失 | 原生格式采用官方解析器允许的 JSON/JSONC 范围；预览不写入，应用检查并发，恢复保留后续无关内容 |
| 共享入口只有序列化成功 | 从真实 Pi CLI 加载共享与直连，发现工具并完成合成 MCP 调用；与模型侧调用分开记录 |
| 旧后台忽略新增客户端 | 提升管理 API；旧服务收到请求前拒绝新盘点和 Pi 原生变更 |
| WorkBuddy 文件路径正确但客户端忽略 | 由 mcplink 事务写入唯一名称的 STDIO 直连、HTTP 直连及共享 Bridge；从真实应用核对加载并调用工具 |
| WorkBuddy 接受的格式与旧隔离测试不同 | 5.9.3 用户读取器使用 JSON.parse；拒绝 JSONC，保留无关 JSON 偏好；隔离读取器也须使用严格 JSON |
| WorkBuddy 原生文件的工具黑名单被静默忽略 | 5.9.3 从独立工具策略读取禁用列表；不把 user mcp.json 的 disabledTools 当成已生效限制，带过滤连接使用共享代理 |
| WorkBuddy 单一超时被拆错 | 核对实际数值单位与初始化/请求预算；只在规范启动与请求超时都可等价表示时导出，否则拒绝并提示共享 |
| WorkBuddy 仅缓存生效 | 退出进程后以正常参数重启，再次发现和调用合成服务；不以配置文件或绿色状态代替调用 |
| 验收污染用户环境 | 仅恢复本次操作与删除本次合成条目；保留其他内容，停止专用后台和 fixture；实机与隔离结果分别记录 |

工件保存在忽略的 `artifacts/e2e/`。macOS 实机验收不等于 Windows 或其他客户端版本通过。
