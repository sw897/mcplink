# Agent 配置适配：失败方式与验收

先完成远程 MCP 修复的阶段门禁，再按 Claude Code user → 显式 local/project → OpenCode 实施。官方契约核对于 2026-11-08：[Claude Code 作用域](https://code.claude.com/docs/en/mcp#mcp-installation-scopes)、[OpenCode MCP](https://opencode.ai/docs/mcp-servers/)、[OpenCode 配置](https://opencode.ai/docs/config/)。原生客户端版本、文件事务与真实工具调用分别记录。

| 失败方式 | 预期 |
| --- | --- |
| Claude Code user 与 local 共用 `.claude.json` | user 只编辑根 `mcpServers`；local 只编辑显式项目键下的 `mcpServers`，保留其他项目和偏好 |
| 项目 `.mcp.json` 与 local 混淆 | 来源明确标明作用域及项目；不递归扫描或猜测项目，不修改审批、信任及权限设置 |
| 同一文件多个作用域、同名服务 | 以作用域和项目定位条目，可批量写入独立条目；冲突按实际条目位置判定 |
| local/project/user 同名覆盖 | 整项覆盖，不合并字段；标明仅针对已添加项目的优先级，避免声称已加载或已批准 |
| 插件、企业托管或未知配置 | 保持只读；以别的 Agent、别名路径或重复登记不能提升写权限 |
| Claude Code 启停字段不能等价转换 | 不向服务条目写入客户端不支持的 `enabled`；项目级启停/审批由原客户端维护，明确拒绝无等价语义的操作 |
| 损坏 JSON、重复键、非对象根/服务表 | 隔离并给出脱敏错误，写入前失败，不吞掉未知配置或覆盖错误文件 |
| JSON/JSONC 编辑 | 保留无关字段、注释、格式和其他服务；恢复只操作目标条目 |
| 预览后外部修改、符号链接、应用中断 | 复用现有哈希检查、备份、原子写入及恢复；不覆盖并发编辑 |
| OpenCode 旧版或混合服务表 | 仅接受当前 `mcp.servers.<name>` / `disabled`，拒绝旧版服务表与 `enabled`，不自动迁移原配置 |
| 空文件或没有 MCP 设置 | 按当前配置格式读取为空服务表，不要求选择历史版本，不产生版本不明确警告 |
| 已停止使用的版本参数或旧后台 | CLI 不再提供 `--layout`；RPC 拒绝版本选择参数，API 6 前的后台在 OpenCode 配置操作发送前失败 |
| 本地进程命令数组、环境变量、工作目录 | 正确拆分命令与参数，保留宏引用和相对路径上下文；不能等价托管的字段明确失败 |
| 原生客户端与托管层的变量语法冲突 | OpenCode 字面 `${…}` 不能被托管层静默展开；Claude `${NAME}` 与托管 `${env:NAME}` 双向转换，保留环境变量名、缺省值及原生语义，不能套用托管项目变量含义 |
| 变量默认值中包含凭据 | 管理输出只显示无缺省值的纯环境变量引用；默认值按其他环境凭据遮蔽，编辑中的遮蔽值保留原定义 |
| HTTP OAuth、专用客户端参数及未知字段 | 直连保留同客户端字段；不把原生登录缓存当作托管 grant；跨客户端转换不等价时拒绝或使用已验证的共享入口 |
| 工具筛选及超时语义不等价 | 保留单位及作用范围；不扩大允许工具集合，不静默丢失限制 |
| 新 Agent 的共享入口 | 使用原生字段编码 Bridge 命令、参数及环境，不直接写入内部规范定义；凭据仅保存引用 |
| 后台/凭据更新与已有客户端连接 | 通过同一托管 ID 恢复调用，不重新生成配置或自动换账号 |
| 桌面、CLI、Skill 能力不同步 | Agent 类型、来源参数、命令 Schema、可写能力和文档同步；旧后台在不支持的新 RPC 前失败 |
| 文件写入成功但客户端未批准/未加载 | 区分“配置已应用”“原生客户端已加载”“工具已调用”，不自动更改用户信任选择 |

隔离验收通过实际 CLI、Bridge 与指定版本原生客户端入口执行；先列失败方式再实现，不用复刻实现的单元测试替代验收。合成数据放公开 fixture，私有配置和业务结果不进入源码。macOS、Windows 逐个平台核验，缺少的原生客户端环境单独列出。
