# 办公客户端接入的失败方式

实现前核对的官方入口（2026-11-09）：[WorkBuddy MCP 路径](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)、[WorkBuddy 字段](https://open.workbuddy.cn/docs/connector)、[千问办公连接器](https://docs.qwenwork.cn/features/connectors)、[豆包工作自定义插件](https://www.doubao.com/work/docs/zh-cn/articles/705018132598-plugins)。

| 失败方式 | 预期及验收入口 |
| --- | --- |
| 安装残留误算已安装 | WorkBuddy 复用程序探测与写入门禁；千问办公/豆包工作可离线生成导入配置，安装状态与生成能力分别显示 |
| 猜测私有数据库或配置路径 | 千问办公仅生成官方导入 JSON；豆包工作生成逐项填写的字段，不创建原生来源，不改客户端存储 |
| WorkBuddy 用户与项目来源混淆 | 使用 `.workbuddy/mcp.json`，项目必须显式登记；预览不写文件，应用/恢复保留无关内容与并发检查 |
| 传输、超时与过滤发生语义变化 | WorkBuddy 使用 `streamableHttp`、毫秒连接超时、`disabledTools`；拒绝 SSE 托管、非整秒毫秒、未知 runtime/模板等不能等价执行的选项 |
| 启停或限制被静默丢弃 | 不虚构 WorkBuddy 的启停字段；不支持的直连选项明确拒绝并提示共享，所有客户端的共享入口保留托管限制 |
| 导入配置被误报为接入成功 | 生成或复制不产生绑定与历史写入，不宣称客户端已加载；UI 提供具体导入步骤 |
| 多服务同名、非法模式及旧后台 | 原子拒绝重复名称或无效请求；API 15 前拒绝新客户端操作，不把新命令发给旧后台 |
| 凭据意外泄露或复制无法使用 | 直连需显式选择且提示含明文；共享只含 Bridge 引用，复制保留路径空格、参数边界及环境变量 |
| 共享连接未验证、断开或暂停 | 生成共享入口前复核 ready/active，暂停时说明调用状态；导出 Bridge 实际调用合成 MCP 工具 |
| 界面只有名单没有操作入口 | 服务页及 Agent 页都可选择新增客户端；千问可复制 JSON，豆包可逐项复制字段，小窗口可滚动且操作按钮可见 |

2026-11-10 官方安装包调查后，修改探测前追加的失败方式：

| 失败方式 | 预期及验收入口 |
| --- | --- |
| 官方包名与猜测名称不同，已安装仍显示未安装 | 使用签名校验过的 `QwenWorkCN.app` / `DoubaoWork.app` 实际包名做隔离 CLI 探测；本机实际安装后再核对快照 |
| 把普通豆包当成豆包工作 | 普通豆包的应用包、Windows 程序及旧配置残留不应让豆包工作变成已安装 |
| 空目录或缺少实际程序的应用包被当成安装 | 完整应用包才算已安装，损坏包保持未安装；导入生成能力独立保留 |
| 兼容分支或运行时 API 被误当成原生配置契约 | 分别记录共享 JSON、身份隔离加密存储、会话管理入口和企业市场 API 的适用条件；不根据离线包中的兼容代码开放写入 |

登录后实机验证前追加：

| 失败方式 | 预期及验收入口 |
| --- | --- |
| 实际保存位置与安装包中的兼容路径不同 | 先通过官方界面保存有唯一名称的合成连接器，再核对实际生成文件、数据库记录计数或云端请求，不读取或复制登录凭据 |
| 配置只在内存生效，重启后被覆盖或丢失 | 使用合成 STDIO / HTTP MCP，核对工具发现、调用记录及正常重启后的重新加载 |
| 本地文件写入成功但客户端忽略 | 若找到明文来源，停止客户端后修改本次测试条目，再启动、核对界面和真实工具调用；只有可复现加载才考虑原生适配 |
| 测试污染已有配置或账号内容 | 只操作本次唯一前缀的合成连接器，不修改既有条目或权限；结束前清理本次测试条目并核对原有内容 |

千问原生适配实现前追加：

| 失败方式 | 预期及验收入口 |
| --- | --- |
| 将 JSONC、未验证执行参数或 CLI 连接器当作普通 MCP | 严格 JSON；仅适配已核对的 STDIO / Streamable HTTP 和 `enabled`；拒绝不等价字段，保留 `cliConnectors` 并拒绝跨桶同名 |
| 身份隔离切换后继续写旧 JSON | 检测身份数据库、格式标记及迁移目录，切换为客户端导入；预览后出现标记时，应用和恢复也须拒绝写入 |
| 原生接入使离线导出消失 | 原生来源与导入能力独立；未安装时仍可准备千问 JSON，生成内容不产生绑定或历史 |
| 旧后台把千问继续当作仅导入客户端 | management API 16 前阻止新快照与千问原生操作；使用真实 CLI 验证拒绝发生在旧服务分派前 |
| 只验证序列化，未验证客户端读取 | 隔离 CLI 覆盖预览、应用、启停、冲突和恢复；实机在停机时由 mcplink 写入测试条目，正常启动后调用真实 MCP 工具 |
| 测试服务把旧握手结果冒充新协议发现 | 合成服务仅实现 legacy initialize；对 `server/discover` 返回 Method not found，让支持协商的客户端回退，再验证工具发现和调用 |

2026-11-10 WorkBuddy 5.9.3 实机核验修正：用户文件使用严格 JSON，工具禁用列表由独立策略维护；旧隔离用例的 JSONC 与 `disabledTools` 假设不代表客户端接受。单一超时按实际单位规则同时约束启动与请求，不能只映射连接超时。修正后的验收与证据见 [WorkBuddy 实机验证](../../docs/workbuddy-verification.md)。

通过真实 CLI、独立原生格式解析器和 MCP Bridge 做隔离端到端验证，并在浏览器验证构建后的界面。此隔离脚本不启动厂商客户端；本机安装包与管理入口的调查见[原生管理调查](../../docs/office-native-investigation.md)。以上验证不等于原生客户端加载或模型回合验收。
