# 真实上游：认证与凭据更新验收

先完成 Agent 适配的两平台阶段门禁，再验证真实服务。只读调用使用用户已授权的账号范围；账号脚本与工件留在忽略的验收目录，公开仓库只记录通用契约和实际结论。

| 失败方式 | 验收要求 |
| --- | --- |
| 第三方封装误标为官方 MCP | 从官方页面取得入口或包；记录版本、来源与摘要，核对实际传输和认证归属 |
| Skill 命令代理误当 STDIO 服务 | 先核对是否持续处理 MCP 标准输入；一次性 `tools/list`/`tools/call` 命令不能直接登记为 STDIO 服务 |
| HTTP 工具调用成功但初始化不兼容 | 比较官方代理对照与完整 `initialize`、通知、协议版本和会话流程；分别记录，不能省略握手后宣称完整 MCP 兼容 |
| 标准 OAuth、专用 Token、API Key 混用 | 核对 MCP 入口真正接受的凭据；业务 API 的 OAuth 不自动计为 MCP OAuth，长期 Token 更新不计为刷新令牌轮转 |
| 登录或用户同意缺失 | 交给用户完成官方登录与同意；不把浏览器登录状态或工具盘点当作业务调用已授权 |
| 默认目录或工具包含写操作 | 使用隔离数据/配置目录及明确的只读工具允许列表；尝试被筛掉的写工具须在派发前失败 |
| 凭据无效、撤销或权限不足 | 用合成无效值验证本地更新和失败恢复；真实撤销、账号切换与权限缩减须有相应测试接入，未执行就明确标记 |
| 更新后已有客户端继续使用旧凭据 | 同一托管 ID、两个已建立 Bridge 和已有生成 CLI 通过更新恢复；原生配置只保留引用 |
| 后台重启后调用失效 | 只重启验收拥有的后台，复验原有 Bridge 与 CLI；结果不确定的业务请求不自动重发 |
| 会议或知识库正文进入验收日志 | 凭据只经内存、stdin 与系统凭据库；只记录状态、计数和摘要，不保存业务正文或认证页面截图 |
| 验收残留账号与后台 | 删除临时托管连接及其凭据，关闭拥有的进程与浏览器；单独记录清理结果 |

腾讯会议依据[官方 MCP 文档](https://meeting.tencent.com/support/articles/14/index.html)与[官方 Skill 入口](https://meeting.tencent.com/ai-skill.html)。其专用 Token 长期有效，重置会使旧 Token 失效；验收不重置用户现有 Token，也不据此声明 OAuth 到期、自动刷新或真实撤销已通过。
